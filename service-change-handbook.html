①这次到底变了什么

同一个动作（换人），从「谁都能改、没人留痕」变成「流程化、有审批、有确认、有记录」。

环节过去（老入口直接改）现在（线上化流程）
入口售后 - 售后客户分配页，点「更换」直接改
（过渡期仍可操作，但没有审批、没有交接确认、没有流程留痕 —— 请统一走新流程）		后台 → 交付线上化流程管理 → 服务人员更换流程管理
权限基本没有限制仅售后/文案的直属上级可发起；「售后经理」权限组可发起全量客户
审批无客户所属部门负责人审批，可同意也可拒绝并写明原因
交接群里说一声 / 口头交代原服务人员、新服务人员在后台逐一确认交接完毕
生效时机点一下就生效所有人确认完毕、且归属转移成功后一次性生效
记录无留痕后台历史记录可查 + 飞书群卡片全程留痕
为什么要做这件事 原来更换服务人员「过程缺少统一的业务审批、信息交接确认、过程记录和群内通知」，客户归属在无记录的情况下就变了。线上化后， 只有流程正常走完，才会执行客户归属转移和绩效处理 —— 对主管和经理来说，这意味着：谁换的、为什么换、谁同意的、交接有没有完成，都能追溯。

今天这场宣讲，这一页是最需要大家记住的 —— 每个人只需要关注自己那一行。

两个说法是一回事：表里的「部门负责人」与「经理」指的是同一个角色 —— 客户当前的售后 / 文案归哪个部门管，就由那个部门的负责人（经理）审批。王丹娜（售后经理权限组）拥有最高权限，可发起并查看全部客户的流程。

一句话总结 发起靠主管、审批靠负责人（部门经理）、确认靠当事人自己。任何一环没人做，流程就停在那里，客户归属不会变。

③流程全景：一单走完的 6 步

主链路 4 个状态、2 条支线。左边是正常路径，右边是会被退回或终止的情况。

STEP 1发起流程主管发起，填写更换原因
›
STEP 2业务审批中部门负责人审批
›
STEP 3信息交接确认中原、新服务人员逐一确认
›
STEP 4更换完成归属 + 绩效自动转移
支线 A · 审批拒绝：业务审批中 → 流程修改中 → 发起人修改并重新提交 → 回到业务审批中（审批人按发起人当前部门负责人重新获取）
支线 B · 主动取消：发起人在任一进行中状态点「取消流程」→ 流程终止（不变更客户归属、不产生绩效变化，该客户可重新发起）

④界面上具体怎么点

按角色分开看。每个人只需要记住自己那一段。

4.1 发起人（售后 / 文案直属上级）

  1. 后台左侧菜单 → 交付线上化流程管理 → 服务人员更换流程管理；
  2. 点右上角 发起流程，弹出「发起服务人员更换流程」；
  3. 输入客户 ID 回车搜索（只能搜到本人下级服务人员对应的客户）；
  4. 依次填写 6 个字段（见下表）→ 点 确认发起。
字段必填说明与填写要求
客户 ID必填只支持输入客户注册 ID，回车或点「搜索」执行；搜索成功后展示客户编号、姓名、申请年份、客户状态、当前售后、当前文案
是否客诉必填单选（是 / 否），默认空，必须主动选择；选「是」会在列表里红色高亮
被更换角色必填复选：售后 / 文案，至少选一个，可两个都选
事实梳理必填多行文本，把事情的来龙去脉写清楚（审批人主要看这个）
客户诉求必填多行文本，客户那边提出了什么诉求
意向人员选填可写具体人员，也可写工作年限、服务经验等偏好说明。仅供审批人参考 —— 不限制新服务人员的候选范围，也不会自动带入审批结果

提示：系统本期不会根据「你管的是谁」自动限制角色选项，需要更换哪个角色由业务自己判断，并找到对应的直属上级发起。

4.2 审批人（客户所属部门负责人 / 部门经理）

  1. 在「进行中」列表找到待审批流程，操作列点 审批（该按钮只对部门负责人显示）；
  2. 先选审批结果，弹窗再展开对应填写区；
    • 选 同意：按被更换角色逐行选择新服务人员（必填，可在全公司范围内选，不限部门）+ 选择是否扣分（必填）；
    • 选 拒绝：填写拒绝原因（必填），流程退回发起人；
  3. 点 保存，系统自动流转并同步飞书群卡片。
审批填写的三个硬约束 ① 新服务人员必须在职；② 角色必须匹配（售后的位置只能选售后）；③ 新服务人员不能与原服务人员相同。另外，新服务人员或其直属上级未绑定飞书账号时，系统会拦截提交。

4.3 原服务人员 / 新服务人员（交接确认人）

  1. 收到群里「请完成信息交接并至后台确认」的卡片后，先把交接内容本身交接清楚（客户情况、进度、注意事项）；
  2. 回到后台「进行中」列表，操作列点 确认交接完毕；
  3. 确认后按钮消失（不允许重复确认），群内自动同步进度卡片。
最容易搞错的一点 在飞书群里回复「已确认」不算确认。系统只认后台列表里点的「确认交接完毕」，确认顺序不限，谁先谁后都可以。

4.4 发起人：驳回后修改、随时取消

动作可用状态说明
修改流程流程修改中带入原数据，可改是否客诉、被更换角色、事实梳理、客户诉求、意向人员；没有「只保存不提交」的草稿，「确认并重新提交」一次完成
取消流程业务审批中 / 流程修改中 / 信息交接确认中弹窗内必填「流程终止原因」；终止后
· 不变更客户归属、不执行绩效
· 保留已产生的审批和确认记录
· 该客户可重新发起新流程

提交时系统会重新校验流程状态和操作人身份；如果页面数据过期，会提示「当前流程状态或操作权限已发生变化，请刷新页面后重试」。

⑤6 个最容易踩的坑

宣讲时建议逐条强调，这几条是实操中最容易出问题的地方。

1
在群里回复「已确认」就当交接完成了 ✔ 群里卡片只是通知，必须回后台列表点「确认交接完毕」，系统才认。
2
以为所有人都要确认，人数记成「4 个人」 ✔ 只换售后或只换文案 = 2 人确认；售后和文案都换 = 4 人确认。发起人不参与确认，新服务人员的直属上级也不参与。
3
等着审批人自己在列表里找流程 ✔ 系统已自动 @审批人；如果是审批人视角，请确认自己就是被更换客户所属部门负责人——审批按钮只对负责人显示，别的角色在操作列看不到这个按钮。
4
发起后追问「新服务人员怎么是空的」 ✔ 点开「被更换角色」详情弹窗，新服务人员、是否扣分在审批通过前本来就是空的，审批通过后才会带出来。
5
在意向人员里指定了人，以为审批只能选他 ✔ 意向人员只是给审批人的参考备注，不限制候选范围。要确保换到指定的人，建议提前和审批人对齐口径。
6
同一个客户还有别的交付流程在跑，就去发起更换 ✔ 服务人员更换与换专业、解约、失败退款、离职人员客户交接双向互斥；同一客户同时只能有一条进行中的更换流程，否则会被拦截。

⑥被系统拦住了怎么办

报错不是系统坏了，是校验在保护流程。下表是可能遇到的拦截提示及处理方式。

报错文案触发原因与处理
仅支持对本人下级服务人员对应的客户发起更换流程该客户不在你的下级归属范围内。请确认客户当前售后/文案是否属于你或你的下级；跨组客户找「售后经理」权限组发起。
该客户存在进行中的服务人员更换流程，请先结束该流程同一客户只允许一条进行中的更换流程。先把上一条走完或取消。
该客户的换专业 / 解约 / 失败退款流程正在进行中，请先结束该流程与其它交付流程互斥，先跑完对应流程再发起更换。
该客户正在进行离职人员客户交接，不允许发起在职服务人员更换流程涉及离职交接的客户，走「离职人员客户交接」流程处理。

所选【角色】【姓名】已离职，请重新选择 / 所选人员角色与【角色】不匹配候选人已离职或角色不对（例如给售后的位置选了文案），重新选人。

⑦飞书群与卡片规则

群是「知悉 + 催办」的通道，真正的操作在后台。这两者不要混。

群怎么建、叫什么名

  • 一个客户只维护一个业务流程群。发起时优先复用客户已有的业务预警群/历史流程群，没有才新建；历史流程结束后再次发起，继续复用原群。
  • 群名自动跟随状态：进行中 →【进行中】【客户姓名】【客户ID】服务人员更换流程群；结束后 →【已结束】…（每次状态变化都会同步改名）。
  • 首批入群：流程发起人、所有原服务人员、原服务人员的直属上级、发起人所在部门负责人（审批人）、客户所属销售。
  • 审批通过后追加：所有新服务人员、新服务人员的直属上级。重复人员只加一次；因修改角色而不再参与的人，不会被移出群。

群内会收到哪些卡片

卡片关键内容
已发起原服务人员、被更换角色、是否客诉、事实梳理、客户诉求、意向人员 → @审批人 处理
修改后重新提交修改后的完整信息 → @审批人 重新审批
审批通过按角色展示「原服务人员 → 新服务人员」→ @所有原、新服务人员 完成交接并至后台确认
审批未通过审批人 + 拒绝原因 → @发起人 修改后重新提交
交接确认进度本次确认人 + 当前进度（如 1/4）+ 每人确认状态 → @尚未确认的人
更换完成最终归属对照表 → @所有人 知悉
流程终止操作人 + 终止原因 → 客户归属未发生变化，@所有人 知悉
客户归属转移失败失败原因 → @最后一位确认人 + @发起人，联系产研处理后重新确认

每张卡片都带「查看详情」按钮，点击直达后台列表并自动按客户 ID 筛选（仍受本人数据权限限制）。卡片不展示是否扣分。

两个要知道的限制 ① 本期没有超时提醒，只有业务操作或状态变化时才发卡片；② 飞书接口异常（建群、拉人、发卡失败）不会回滚业务数据，业务侧可手动拉人进群，本期没有「重新发卡 / 重新拉群」按钮。

⑧分角色操作清单

可直接打印或发到群里，按角色对照执行。

我是发起人（主管）

  • 确认客户当前售后/文案在我或我的下级名下
  • 确认客户没有进行中的换专业/解约/失败退款/离职交接
  • 确认相关人员的飞书账号都已绑定
  • 后台发起流程并填写：是否客诉、被更换角色、事实梳理、客户诉求、意向人员
  • 被驳回后修改信息并重新提交
  • 要中止时填写终止原因取消流程

我是审批人（部门负责人）

  • 关注飞书群里的待审批卡片（或后台「进行中」列表）
  • 审阅事实梳理与客户诉求
  • 选择同意时：逐角色选新服务人员（在职、角色匹配、非原服务人员）
  • 逐角色选择是否扣分
  • 选择拒绝时：写明拒绝原因
  • 确认新服务人员及其直属上级已绑定飞书

我是交接确认人（原 / 新服务人员）

  • 看到群里「审批通过」卡片后，主动和对方对接客户情况
  • 完成实质交接（进度、材料、注意事项）
  • 回后台列表点「确认交接完毕」
  • 确认后不要重复操作（按钮会消失）
  • 若是最后一名确认人：确认前再核对一遍交接确实完成
  • 确认失败提示数据异常时，联系产研处理后再确认

⑨常见提问 Q&A

只换售后，不换文案，可以吗？

可以。被更换角色支持「仅售后」「仅文案」「售后和文案同时更换」三种情况。只换一个角色时，需要该角色的原服务人员和新服务人员共 2 人确认。

组合里的客户，别的组的人能帮我发起吗？

不能。售后经理权限组（如王丹娜、蔡丽佳）才可发起全量客户；普通组长只能发起下属组员的客户。跨组客户请找售后经理权限组成员发起。

审批人是谁？我可以自己审批自己的流程吗？

审批人是发起人当前所在部门的部门负责人。如果发起人本人就是部门负责人，允许自行审批。每次首次发起或修改后重新提交，都会按发起人当前组织关系重新获取审批人。

新服务人员能不能跨部门选？要不要提前沟通？

可以跨部门，审批人可在全公司范围内选择符合条件的人员（不限制部门）。但建议提前线下对齐，避免对方不了解情况或绩效口径有分歧。

审批人点了「拒绝」，这单要重新发起吗？

不用。被拒绝后流程进入「流程修改中」，发起人在「进行中」列表找到这条记录，点「修改流程」带入原数据修改，再点「确认并重新提交」就回到业务审批中（审批人按你当前的部门负责人重新获取）。注意没有只保存不提交的草稿；确实不换了，就在同一行点「取消流程」，填终止原因后结束，不影响客户归属和绩效。

流程卡住了，客户归属会提前变吗？

不会。只有全部确认完毕且归属转移成功后，客户归属才变更；中途取消、终止、驳回都不会改变客户归属，也不会产生绩效变化。

审批通过后，新服务人员突然离职或换岗怎么办？

本期不支持在线改派。系统会在最后一人确认时复核新服务人员是否仍在职、角色是否匹配，异常会拦截并提示联系产研处理。

客户能看到或收到通知吗？

不会。本流程仅在内部飞书群通知，不向客户发送任何消息。

能看到别人发起的流程吗？

普通用户可查看：自己发起的、自己所有下级发起的、以及本人作为原/新服务人员参与的流程。「售后经理」权限组可查看全部流程。
